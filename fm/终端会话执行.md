# 终端会话执行说明

这份说明只规定要做成什么样、按什么顺序做。照此实现前先写测试，测试没锁定的行为不许先改程序。

## 结论

agent 用的终端就是 webos 上的那个终端。一个会话等于一个桌面窗口，窗口后面是系统上的一个真 shell。可以同时有多个会话。没有一个常驻、所有命令都往里塞的终端。人开的和 agent 开的是同一种东西。

浏览器继续用现在的 WebSocket 看画面、送按键。agent 在同一个服务进程里直接操作会话对象，不给自己再连一条 WebSocket，也不再调用 `apps/nextagent/maf_tools/terminal_tool.py` 里的 `terminal_tool`。

## 现在已经有的，不要另做一套

依据 `fm/backend/terminal.py`、`fm/frontend/js/apps/terminal.js`、`fm/backend/desktop.py`、`fm/frontend/js/desktop-os.js`、`apps/nextagent/toolkit/terminal.py`、`apps/nextagent/toolkit/process.py`。

已经有、必须沿用：

- 系统 shell：Windows 是 PowerShell，Linux 是登录交互 bash。启动目录必须是真实存在的目录。
- 会话登记：`POST /api/terminal/start`、`GET /api/terminal/active`、`POST /api/terminal/close`。
- 画面通道：`/api/terminal/ws?id=`。后来连上的人先收到 `\0` 加上此前全部输出，shell 进程还在。刷新不断进程。这条已有测试 `test_refresh_keeps_the_shell_and_replays_output`。
- 按键原样写入 shell，输出广播给所有订阅者。
- 窗口关掉时，页面向这条 WebSocket 发送 `{type:close}`，服务端停掉 shell。
- 桌面遥控：浏览器连 `/api/desktop/screen?desktopId=`，调用方指定 desktopId 执行操作。没有默认屏幕。屏幕不在线就立刻失败，不排队。
- 终端窗口刷新后能连回，靠会话号，不靠一个会变的临时窗口号。`fm/frontend/js/app.js` 的恢复走 `FMTerminal.reattach`。

现在对不上、这次要补的：

- 开始菜单打开终端时，窗口号被固定成 `terminal:empty`（`fm/frontend/js/kodApp.js` 的 launch）。第二个终端不会出现，只会聚焦第一个。这和多会话矛盾。
- 服务端建好会话不会弹出窗口。
- 终端窗口没有「打开这个会话、聚焦、关掉」这类可编程操作。它只有 describe。
- agent 的 terminal / process 走的是另一套子进程，桌面上看不见。
- 对话点停止会杀掉那次命令的子进程。接到可见终端上之后，这个行为要改，见下文「停止对话」。

## 一个会话是什么

一条会话同时有这些，缺一个就不叫终端会话：

- 一个系统 shell 进程
- 一份输出缓冲（shell 打出来的原始字节，包含颜色和下面说的结束标记）
- 零个或一个桌面窗口，窗口号永远是 `terminal:` 加上会话号
- 一个 desktopId，记录它显示在哪一块屏幕上

状态只有这几个：`starting`、`idle`、`running`、`exited`、`closed`。

- `starting`：shell 已拉起，钩子还没就绪。这时不许交给 agent，也不许给人操作。
- `idle`：停在提示符，可以提交下一条命令。
- `running`：有一条命令还没结束。
- `exited`：shell 进程没了，窗口可以还在。输出还在这次关闭动作返回之前可读。
- `closed`：窗口和登记都没了。

服务进程重启后，内存里的会话全部消失。不恢复进程，不假装会话还在。页面刷新后连回失败，就按现在的恢复逻辑报「终端进程已经不在了」。

## 命令结束怎么知道

人是看提示符回来了。agent 读的是同一条输出，但提示符文字会被用户配置改掉，不能靠认提示符。

shell 在自己的提示符函数里打两个不可见标记。标记不进用户看见的正文。

- 提示符出现：`ESC ] 133 ; A BEL`，也就是字节 `\x1b]133;A\x07`
- 上一条命令结束：`ESC ] 133 ; D ; 退出码 BEL`，退出码是十进制，例如 `\x1b]133;D;0\x07`

规则：

- 提示符函数的第一件事是把「上一条是否成功」存下来，然后再做别的。否则函数自己的命令会把结果冲掉。
- 有上一条命令时，先打结束标记，再打提示符标记。
- 第一次提示符只有 A，没有 D。会话等到这个 A 才从 `starting` 变成 `idle`。
- Windows 上，退出码用这条命令自己的结果：PowerShell 命令成功为 0、失败为 1。不许把上一条外部程序留下的 `$LASTEXITCODE` 套到 `cd` 这种命令上。
- Linux 上，退出码用这条命令结束时的 `$?`。同样必须在提示符钩子的第一条就存下来。
- 钩子在用户的 profile 跑完之后装上，避免 profile 把钩子覆盖掉。装钩子的过程不能出现在窗口回放里。做法是：缓冲里第一次 A 之前的字节全部丢掉，窗口和 agent 都从这次 A 之后开始看。profile 自己打印的欢迎语也会因此看不到。这是既定结果，不要再把欢迎语拼回去。
- 发给窗口的仍是原始终端字节，颜色和光标靠它。先不在服务端删标记。用测试确认 xterm 不会把标记画成乱码。若测试看到乱码，只在送进 xterm 之前去掉 `OSC 133` 这一段，其它字节不动。
- 交给模型的文本去掉标记，并走现在已有的 ANSI 剥离。退出码从 D 标记读。没有 D 标记就没有退出码，不许填 0。

前台等待就是：提交之后，等到这次提交之后出现的下一个 D 标记。等到了，状态回到 `idle`，返回这段输出和退出码。

超时没等到：状态保持 `running`，窗口留着，返回已经有的输出，`status` 为 `running`。不杀进程。这和现在工具「前台超时就转成后台会话」一致。

## 回车字节

画面上按回车，xterm 的 `onData` 发的是 `\r`，`terminal.js` 原样送进 WebSocket。agent 提交一行必须写 `\r`，不能写 `\n` 或 `\r\n`。

用测试锁定 Windows 和 Linux 都是这一个字节能执行命令并等到结束标记。测试失败就停，不许改成「先试一种、不行再试另一种」。

## 桌面是哪一块

没有默认屏幕。这块屏幕的 id 来自对话所在的那块桌面，不从在线列表里挑。

- `fm/frontend/js/apps/agent.js` 打开 iframe 时，把 `DesktopLink.desktopId` 放到地址上：`/agent?desktopId=`。
- agent 页面连上聊天 WebSocket 时，auth 的 data 里带上这个 desktopId。依据现在的 auth 在 `apps/nextagent/static/js/ws.js`，字段是 `data.threadId`，在同一处加上 `desktopId`。
- 服务端把这个 id 放进当前轮上下文。工具只读这里。
- 没有这个 id，或者这块屏幕不在线：直接失败。不创建 shell。

人直接打开 `/agent` 而不是从桌面进，就没有 desktopId。这时终端工具失败。不建一个看不见的 shell。

## fm 终端要加的能力

浏览器的四个地址保持不变：`/home`、`/start`、`/active`、`/close`、`/ws`。agent 不走 HTTP 调自己。

在会话对象上增加这些操作，供本进程里的工具调用。失败用现有方式报错（参数不对是 400 那种明确错误，会话不存在是找不到），不要吞掉。

### 打开

输入：目录、desktopId、对话的 session_key（用来把完成通知送回当前对话）。

顺序固定，不能换：

1. desktopId 为空或该屏幕不在 `_desktops` 里：失败，到此为止。
2. 目录不是已存在的目录：失败，到此为止。沿用现在 `open_shell` 的判断。
3. 创建 shell，状态 `starting`。窗口号定为 `terminal:` 加会话号。
4. 装钩子，等到第一个 A。等到之前，会话还不能被列出给人或 agent 去输入。启动超时（建议 20 秒，与桌面命令等待同级）：停掉 shell，失败。
5. 叫这块桌面执行 `terminal.open`。桌面把窗口挂到这个会话号上。
6. 桌面失败或超时：停掉 shell，再让桌面执行 `terminal.close`。窗口若已经挂上但会话没了，窗口必须自己关掉，不能留空窗口。然后失败。
7. 成功后状态是 `idle`。返回会话号、窗口号、pid、目录。

人从开始菜单打开：同样走「新建一个会话」，窗口号也是 `terminal:` 加会话号。每次点击都是新会话。点任务栏上已有的按钮才是聚焦那一个。默认目录仍是用户目录（现在的 `/api/terminal/home`）。agent 不写目录时用工作区目录，沿用 `apps/nextagent/toolkit/terminal.py` 里 `_resolve_workdir`。这两个默认不要并成一个。

### 提交一行

输入：会话号、一行文本（不含回车）。

- 会话不是 `idle`：失败。上一条还在跑时，不能用「再跑一条命令」这条路。要在程序运行中打字，走下面的原始输入。
- 写入「文本 + `\r`」。状态变为 `running`。记下这次在缓冲里的起点，和这一行文本。
- 字节只写进 shell。靠 shell 回显出现在窗口里。不要再往 xterm 里写一遍。

### 原始输入

输入：会话号、一段字节（字符串）。

- 会话是 `running` 或 `idle` 才可以。`exited` / `closed` / `starting` 失败。
- 原样写入，不加回车。用于回答程序的提问，或发送 Ctrl+C（`\x03`）、Ctrl+D（`\x04`）。
- 同样只写进 shell。

### 读输出

输入：会话号、起点偏移、可选行数限制。

- 返回缓冲里从起点之后的新文本（给模型的那份：无标记、无 ANSI）、新的偏移、状态、若已经有这次命令的 D 标记则带退出码。
- 偏移是字节或字符位置，同一次会话内单调增加。调用方用上次返回的偏移接着读。不要另做「只返回新增」的第二套缓冲。

### 等待

输入：会话号、超时秒数。

- `idle`：立刻返回，说明现在没有命令在跑。
- `running`：阻塞到出现 D 标记、超时、或对话被停止。
- 超时：保持 `running`，返回已有输出。
- 对话停止：只结束这次等待，返回 `interrupted`。不关窗口，不杀 shell。见「停止对话」。
- shell 自己退出（人输入了 exit）：状态 `exited`，记下进程退出码。没有退出码就失败，不许写成 0。窗口留着，和现在连接断开后窗口还在一样。

### 关闭

输入：会话号。

这是关掉整个终端，等于人关掉窗口。

1. 先把当前输出抄出来，放进返回值。
2. 桌面还在：执行 `terminal.close`。窗口的现有关闭逻辑会发送 `{type:close}`，服务端停 shell。不要在这之前先把 shell 杀掉，否则窗口会留下一条「连接已关闭」还不消失。
3. 窗口已经不在：若 shell 还在登记里，停掉它。返回 `already_closed` 和刚才抄下的输出。
4. 桌面不在线：停掉 shell。返回错误，说明桌面不在、会话已停。不能留下一个没有画面的 shell。

`process` 里的 close 不是这个。见下文工具对照。

### 列出

返回这块服务上所有未 `closed` 的会话：会话号、窗口号、目录、pid、状态、desktopId。包括人开的和 agent 开的。

## 桌面要加的两个操作

加在 `fm/frontend/js/desktop-os.js` 的 operations 里，和现有 `explorer.open` 一样由桌面自己执行。后端不复制一份操作表。

- `terminal.open`：参数 `sessionId`、`path`。调用现有 `FMTerminal.attach(sessionId, path, "terminal:" + sessionId)`。窗口已在就聚焦，不另开一个，不另起一个 shell。挂上时若会话已经不在 `/api/terminal/active` 里，关掉这个窗口并报错。
- `terminal.close`：参数 `sessionId`。关掉窗口号 `terminal:` 加这个会话号。窗口不存在就报找不到。

服务端在 `fm/backend/desktop.py` 增加一个本进程能调用的执行函数，走现在的 `DesktopConn.call`，等待上限用现有的 20 秒。工具在工作线程里调用时，用和 `notify_fs_changed` 相同的方式丢回桌面那条事件循环并等待结果。不新开一条桌面协议。

agent 往某个会话提交或原始输入时，再执行一次聚焦这个窗口，让人看见正在打的字。读输出和等待不聚焦，避免抢焦点。

## agent 工具怎么调用

模型仍用现在两个工具名：`terminal` 和 `process`。改的是它们背后做的事，以及给模型的说明。说明要写成「打开一个终端窗口、往里打字、看屏幕、关掉窗口」。

`pty` 这个参数去掉。现在总是真终端。模型再传 `pty=false` 就报错，说明这个终端始终是系统终端。

`terminal_tool` 不再被工具调用。`apps/nextagent/test_scan_limits.py` 改为走工具入口。`terminal_tool.py` 这次不删，避免把无关的旧环境代码卷进来。确认没有其它调用之后再单独删。

### terminal

参数：`command`、`session_id`、`workdir`、`timeout`、`background`、`notify_on_complete`、`watch_patterns`。

- 没有 `session_id`：按「打开」新建一个会话。`workdir` 空则用工作区目录。
- 有 `session_id`：必须是已有会话。再传 `workdir` 就报错，让模型自己在会话里 `cd`。不要偷偷帮它改目录。
- `command` 为空且没有 `session_id`：只打开，停在提示符，返回会话号。状态 `idle`。
- `command` 为空且有 `session_id`：报错。
- `command` 非空：对目标会话「提交一行」。
- `background` 为假：提交后「等待」，直到 D 标记或超时。超时则 `status=running`，带会话号和已有输出，窗口留着。
- `background` 为真：提交后立刻返回会话号，不等待。窗口留着，状态 `running`。
- 两个通知开关都开：沿用现在的规则，监视作废，返回里写明原因。依据 `terminal_tool` 里 `_resolve_notification_flag_conflict`。
- 只开 `notify_on_complete`：出现 D 标记时，往 `process_registry.completion_queue` 放一条和现在完成事件相同字段的通知（`type=completion`、会话号、`session_key`、命令、退出码、输出尾部）。仍由 `apps/nextagent/process_notify.py` 取走。不新做通知通道。
- 只开 `watch_patterns`：新输出里命中关键字就往同一个队列放监视通知。同一会话至少间隔 15 秒才发下一条，中间的命中丢掉。不把「监视太密就改成结束时通知」搬过来。结束通知只由 `notify_on_complete` 决定。

返回字段仍是模型已经在用的那些：`output`、`exit_code`、`session_id`、`status`、`error`。`status` 使用 `idle`、`running`、`exited`、`error`、`interrupted`。前台正常结束时 `exit_code` 来自 D 标记，`status` 为 `idle`。

### process

参数不变：`action`、`session_id`、`data`、`timeout`、`offset`、`limit`。

- `list`：上面对「列出」的结果。不再按隐藏子进程列举。
- `poll`：状态、pid、已运行秒数、输出尾部。已结束则带退出码。不把会话标成「输出已被取走」。
- `log`：按行分页读给模型的文本。`offset=0` 时取最后 `limit` 行，与现在 `process_registry.read_log` 一致。
- `wait`：上面对「等待」。
- `write`：原始输入，不加回车。
- `submit`：等于提交一行。会话必须是 `idle`，否则报错。程序运行中要回答提问，用 `write`，需要回车就在 `data` 里自行包含，或再 `write` 一个 `\r`。
- `close`：向 shell 写 `\x04`（Ctrl+D）。不关窗口，不杀进程。停在提示符时，shell 通常会因此退出，状态变成 `exited`，窗口还在。这和人按 Ctrl+D 一样。
- `kill`：上面对「关闭」。停 shell 并关窗口。返回里带关闭前的输出。

人在窗口里打的字和 agent 打的字进同一个 shell，会交错。这是同一条终端，不加锁去挡人。

## 连回

三件事不要混：

1. 页面刷新。shell 不动。页面用会话号重新 `attach`，WebSocket 用 `\0` 回放。窗口号仍是 `terminal:` 加会话号，所以刷新前后是同一个窗口身份。desktopId 在 `sessionStorage` 里本来就会保住。
2. agent 再次操作。用会话号做提交、读取、等待、关闭。不新建 shell，不新建窗口。会话已 `closed` 或不在了：返回找不到。
3. 桌面的 WebSocket 断了又连上。desktopId 不变。正在等的那条桌面命令会失败（现有 `fail_all`）。失败就失败，工具把错误返回。不自动重试。

shell 退出但窗口还在：会话是 `exited`，agent 可以 `poll` / `log` 看到最后输出，再 `kill` 把窗口关掉并从列表移除。不在进程一退出时自动关窗口。

## 停止对话

人在对话里点停止：若 agent 正堵在「等待」上，这次等待返回 `interrupted`。窗口留着，shell 留着，正在跑的命令留着。

要停掉终端里的程序，和人一样：`write` 一个 `\x03`，或 `kill` 关掉整个终端。不再因为对话停止去杀 shell。

## 人和 agent 同时用

- 人点开始菜单：新会话、新窗口、用户目录。
- agent 不带会话号调用：新会话、新窗口、工作区或指定目录，出现在这条对话所在的那块屏幕上。
- 谁拿到会话号，谁就可以往里输入。列表两边都看得到。
- 关掉窗口等于关掉这个会话。另一边下次再操作，得到找不到或 `already_closed`。

## 先写的测试

测试写在现有 `fm/tests/test_terminal.py` 和 agent 工具测试旁边。先红，再改程序。每条只锁一件事。

1. `\r` 在 Windows 和 Linux 上都能让 shell 执行一条会打印记号的命令，并在输出里出现 D 标记，退出码为 0。
2. 失败的命令，D 标记里的退出码不是 0。
3. 同一会话里 `cd` 到另一个目录后再查当前目录，还在新目录。另一个新会话仍在它自己的启动目录。
4. 窗口回放里看不到钩子安装那段文本。
5. 第一个 A 出现之前，会话不能被提交。启动超时则没有残留进程。
6. 没有 desktopId，或屏幕不在线：不创建 shell。
7. 桌面打开窗口失败：shell 被停掉，进程不在了。
8. 会话已关闭之后，迟到的 `terminal.open` 不会留下窗口。这一条在前端用现有预览或桌面操作测试锁住。
9. 前台等待在 D 标记出现时返回，输出里没有标记字节。
10. 前台超时后进程仍在，状态 `running`，再次等待还能等到结束。
11. `background` 立刻返回，窗口会话已是 `running`，结束标记之后状态回到 `idle`。
12. `running` 时再 `submit` 一条新命令：失败，shell 里不会多出这条命令。
13. `write` 在 `running` 时可以把字节送进正在跑的程序。
14. `close` 只发送 `\x04`，不把会话从列表里删掉。
