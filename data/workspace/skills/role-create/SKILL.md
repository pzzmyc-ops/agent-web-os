# 创建角色

用户说「加一个产品经理一起聊」「建个角色帮我审代码」「把刚才那个角色改得再严厉点」时用这个技能。
角色的增删改和加入对话全部用 `role_manage` 工具完成,不需要动文件、也不用调 HTTP。

## 1. 角色是什么(决定了 system_prompt 该怎么写)

一张角色卡 = `name` + `avatar`(1-2 字)+ `system_prompt`。角色被加入某个对话后,那个对话的
每一轮变成群聊:

- **你是总协调者**,起始发言人,负责分派、必要时自己动手、最后收尾。
- **每个在场角色是一个独立参与者**:它的 `system_prompt` 就是它的全部设定,它和你一样能读写
  工作区、开终端、调各种工具。
- 谁发言由**交接**决定:你(或别的成员)调 `handoff_to_xxx` 把控制权交出去。交接工具的说明
  取自角色卡 —— **`system_prompt` 的前 200 字就是别人判断「什么时候该找它」的全部依据**。
- 「做完把控制权交回协调者」这句协议由系统自动注入,**不要写进角色卡**。

## 2. system_prompt 怎么写

按这个骨架写,第一句永远是职责:

```
你负责<职责范围>。<专业背景/立场>。
工作方式:<怎么干活,比如先看什么、按什么标准、要不要动手改>
输出:<篇幅、结构、语气>
边界:<不做什么 / 什么情况交给别人>
```

✅ 好例子(职责在第一句,有立场,有可执行的输出约束):

```
你负责需求拆解和优先级排序,是个做过 5 年 B 端产品的产品经理。
拿到一个想法先问清目标用户和成功指标,再拆成可交付的小步骤,每步标出价值和成本。
输出:结论先行,列表形式,不超过 300 字。
边界:不评价技术实现方案,那部分交给工程角色。
```

✅ 另一个(性格类角色也要有职责):

```
你负责挑刺 —— 专门找方案里没想清楚的地方,是个刻薄但从不无理的评审。
每次只挑最致命的 2-3 个问题,每个问题都要说清「在什么情况下会出事」。
输出:直接说问题,不铺垫、不安慰,不给出你自己也没把握的替代方案。
```

❌ 反例:

- `你是一个专业的AI助手,会尽力帮助用户。` —— 没职责、没立场,交接说明等于空的,协调者永远不知道该找它。
- `你是产品经理。` —— 太短,和只写个名字没区别。
- `...做完后请把控制权交还给协调者,并在回复末尾署名。` —— 协议由系统注入,署名没人看。
- 把用户的原话整段抄进去 —— 角色卡是给这个角色**每一轮**读的设定,不是这一次的任务描述。任务照常
  由你在对话里交接时说明。

`name` 用职务或人名(2-6 字),`avatar` 用 1-2 个字(如 `产品`、`挑`),留空则前端取名字首字。

## 3. 流程

用户要一个角色参与对话时,一步到位:

```
role_manage(action="create", name="产品经理", avatar="产品",
            system_prompt="你负责需求拆解和优先级排序,...",
            join=true)
```

- 建好但先不参与:去掉 `join`(比如用户说「先建几个备用」)。
- 已有的角色拉进来:`role_manage(action="join", role="产品经理")`。
- 不知道有哪些角色:`role_manage(action="list")` —— 同时告诉你当前对话里在场哪些。
- 改设定:`role_manage(action="update", role="产品经理", system_prompt="...")`,只改传了的字段。
- 请出去:`action="leave"`(卡还在角色库);彻底删掉:`action="delete"`(不可撤销)。

用户只说「加个X」没说职责时,按常识把职责补全并**在回复里一句话说明你给它设了什么定位**,
让用户能纠正;信息缺得多、方向可能完全跑偏时(例如「加个能帮我处理公司业务的角色」),
先用 `clarify` 问一句。

## 4. 注意事项

- **join 从下一轮生效。** 本轮的参与者名单在收到用户这条消息时就定了,新角色这一轮不会开口。
  所以别说「它现在就来了」,要说「下一条消息起它就参与」。
- **在场角色控制在 3 个以内。** 群聊按发言顺序串行跑,人多每轮更慢,也更容易互相打转。
- **角色重名会被拒绝**,想改就用 `update`。
- 角色能力和你一样(能写文件、能开终端),所以设定里该说清它的边界 —— 别让一个"文案角色"
  顺手去改代码。
