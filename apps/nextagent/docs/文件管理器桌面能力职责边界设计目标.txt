文件管理器桌面能力职责边界（已落地）

============================================================
一句话
============================================================
文件管理器是被动接口：窗口、app、能力、参数，按 winId 执行。
agent 侧没有桌面专用工具，只有一份 skill：终端跑脚本，脚本连桌面。


============================================================
两层
============================================================
文件管理器（被动，拥有一切执行）
- 真源：窗口和 app 实例，都在浏览器页面里。
- 窗口级操作在 DesktopOS.operations 一张表里自报：名字、说明、参数 schema、是否只读。
  加一个操作只改这张表，调用方零改动。
- 每个 app 自己登记能力和参数（文本编辑器、Office、资源管理器……）。
  DesktopOS 只转发：app.describe / app.capabilities / app.invoke，不认识具体 app。
- 对外两条 WebSocket（fm/backend/desktop.py）：
    /api/desktop/screen?desktopId=<id>   浏览器页面报到，执行下发的命令
    /api/desktop/control                 调用方，第一条消息带 token，之后 list / exec
- 后端不存操作清单，不认识任何 agent，不当网关：只做「列出在线屏幕、把命令送到指定
  那一块、把回执原样返回」。

agent（消费，只有说明）
- skills/builtin/desktop-control：SKILL.md + scripts/desktop.py。
- 模型用已有的 terminal 跑脚本，脚本用 WS 说话。没有 desktop_* 工具，没有 app_invoke，
  没有服务端桌面通道。
- skill 不抄任何 app 的参数表：操作和能力都在运行时问桌面。


============================================================
一块屏 = 一个浏览器标签页
============================================================
desktopId 由页面生成，存 sessionStorage：刷新后不变，另开标签页就是新的一块。
窗口存档也存 sessionStorage，所以两块屏互不覆盖（代价：关掉标签页不再恢复窗口）。

命令必须指明 desktopId，没有「默认那块屏」。不在线就立刻失败，不排队。
刷新后 desktopId 不变，但窗口是重建的、winId 会变 —— 调用方不能跨刷新记住 winId。

多块屏在线时由调用方（模型）问用户操作哪一块，文件管理器不替谁做选择。


============================================================
鉴权
============================================================
调用方要 token，与 agent 用的是同一个固定 token（server.py 注入 FM_API_TOKEN）。
浏览器页面报到不要 token：能打开那个页面的人本来就坐在那块屏幕前。


============================================================
模型怎么认目标
============================================================
os.snapshot 给出每个窗口的 winId、app、标题、是否最前，以及该 app 自报的 state。
写操作只认 winId，标题不参与路由。

选 winId 靠：
- app（aceEditor / onlyoffice / explorer …）
- state 里的路径（编辑器 activePath，Office path）
- capabilities（有没有要用的那个能力；Office 未就绪则列表为空）
- 用户没指明文件时，才用最前面的窗口

编辑器写操作只打活动标签页；路径对不上就报错。
Office 一个窗口绑一份文档；docType 决定读/写哪类能力。


============================================================
明确不做
============================================================
不把 DesktopOS 搬进 agent。
不在 agent 侧保留任何桌面专用工具或常驻桌面通道。
不让文件管理器认识 agent、发现 agent、承载对话协议。
不把窗口管理写进 Office 或文本编辑器。
不按 app 在 agent 侧拆专用工具。
不另开离线改文档引擎（docbuilder 已删）。
不把对话、计划、角色塞进文件管理器。


============================================================
iframe 边界上还剩什么
============================================================
只剩一条：agent 改了文件 → fs_changed → postMessage fm:fs-changed → 资源管理器刷新。
（static/js/desktop-bridge.js 与 fm/frontend/js/apps/agent.js）
桌面操作不走 iframe，任何调用方都直连 /api/desktop/control。
